## Decisions

### Detector design

- **Mirror sibling detector shape.** Same argparse surface, same exit-code
  model (0 / 1 / 2), same severity-floor ladder, same `_checklib` shared
  primitives, same `_split_functions` brace-depth heuristic as
  `check-foreign-host-401-scoping.py`. Implementer convention is now
  established by the FH-1 / D1 / D5 detectors that landed in the same
  swarm — staying inside the convention keeps the verify-pr wire-in
  trivial and the failure messages mechanical-greppable.
- **In-scope filter on diff mode.** Diff-mode scans only files under
  `Palace/Network/` and `Palace/SignInLogic/` — the architect's contract
  scope. Scan-mode (used by tests) walks the full Palace/ tree so fixtures
  in `<tmp>/Palace/Network/` still flow through `_scan_file`.
- **Two-shape construction detector.** Supports both inline
  `NSError(domain: ..., code: ..., userInfo: ...)` and multi-line
  `NSError(\n  domain: ...\n  code: ...\n  userInfo: ...\n)` forms. PP-3956
  used the multi-line form in `TPPNetworkExecutor.refreshTokenAndResume`,
  so a single-line-only detector would have missed the canonical bug.
  Multi-line detection works by looking ahead 3 lines from an `NSError(`
  opening for a `domain:` argument.
- **Preservation regex set.** Six patterns cover both direct embedding
  (`problemDocument.title`, `problemDocument.detail`, plus `problemDoc.`
  shortened variants) and helper routing (`NSError.problemDocumentKey`,
  `makeFromProblemDocument(`, `makeFromHTTPResponse(`). Any one of these
  appearing anywhere in the function body makes the function "clean"
  for the bug class — the detector's job is to surface NSError
  constructions where NONE of these evidence patterns apply alongside
  a problemDoc in scope.
- **Annotation escape hatch.** `// no-problemdoc-preservation: <reason>`
  on the NSError-construction line or the 3 preceding lines suppresses
  the finding. Same convention as `// no-host-scoping:` (FH-1) and
  `// no-superpartner:` (check-superpartner-spectrum.py). Reviewer-readable
  rationale required; the `--no-verify` escape hatch is for things that
  can't be expressed in code, this isn't one of them.

### Live-survivor verdict

Architect contract predicted "1-4 survivors" because PR #935's commit
body called the original sweep partial ("Sweep of other NSError
constructions in Palace/Network/ — the deferred sweep"). Running
`--scan .` against the worktree returned **0 findings**. The reason:
PR #935 already preserved the problemDoc through the canonical helper
at the only `Palace/Network/` site whose function actually had a
`TPPProblemDocument` in scope.

Verified by manual inspection of every `NSError(domain:` site under
`Palace/Network/` + `Palace/SignInLogic/`:

  - `Palace/Network/TPPNetworkExecutor.swift:494, 510, 526, 626` — all
    inside `refreshTokenAndResume` / `executeTokenRefresh` whose bodies
    DO include `makeFromProblemDocument(...)` (line 604) and direct
    `(error as NSError).problemDocument` binding (line 603). Function-
    level preservation evidence → CLEAN.
  - `Palace/Network/TPPNetworkExecutor.swift:610` — same function, the
    `else` branch of the preservation `if-let`; CLEAN by the same
    function-level evidence rule.
  - `Palace/Network/TPPUserFriendlyError.swift:65, 87` — these ARE the
    helper functions (`makeFromProblemDocument`, `makeFromHTTPResponse`);
    CLEAN by definition.
  - `Palace/Network/TPPNetworkResponder.swift:139, 333, 362, 379` — none
    have a `TPPProblemDocument` in scope (different code paths:
    cancel-error, raw HTTP-failure logging, var-init placeholder). NOT
    the bug class.
  - `Palace/Network/TPPNetworkResponder.swift:624` — uses
    `NSError.makeFromProblemDocument(...)` directly; CLEAN.
  - `Palace/SignInLogic/TPPSignInBusinessLogic.swift:435` — validation
    error path, no problemDoc in scope. NOT the bug class.
  - `Palace/SignInLogic/TPPSignInBusinessLogic+DRM.swift:30` — DRM
    ProfileDoc path, no HTTP body to parse. Explicitly carved out as
    "not the same class of bug" in PR #935's commit body.
  - `Palace/SignInLogic/TPPSignInBusinessLogic+OIDC.swift:285` — OIDC
    delegate-callback dispatch, no problemDoc in scope. Same carve-out.

PR #935's "sweep" defer note covered the symmetric refactor to route ALL
NSError constructions through the helper for consistency. The deferred
LINT (this detector) catches future regressions where someone re-adds
the bug shape; the deferred SWEEP itself wasn't load-bearing because the
remaining sites aren't in the bug class.
