## Summary

Built `scripts/check-lcp-acquisition-recursive.py` (D1-1) — a path-scanning Swift detector that flags any function whose body references both `defaultAcquisition` and an LCP MIME literal (or `expectedAcquisitionType` / `ContentTypeReadiumLCP` constant) without referencing any of `indirectAcquisitions`, `hasLCPAcquisition`, or `indirectChainContainsLCP`. Annotation escape: `// no-lcp-recursive: <reason>`.

Wiped the contracted survivor at `Palace/Audiobooks/LCP/LCPAudiobooks.swift:200-201` — `canOpenBook(_:)` now delegates to `hasLCPAcquisition(_:)`, so all three OPDS feed shapes (`/loans/` XML, `/groups/` JSON Marketplace, OPDS-Catalog wrapping) resolve through the recursive walk regardless of entry point. Detector now returns 0 findings against the live codebase.

Wall-failure entry `.forgeos/wall-failures/2026-06-05-pp4407-lcp-acquisition-recursive.md` retrofits PP-4407 (audiobooks, PR #958) + PP-4454 (LCP PDFs, PR #1008) as a single bug class with `detector_script: scripts/check-lcp-acquisition-recursive.py` frontmatter per Module A's TEMPLATE convention.
