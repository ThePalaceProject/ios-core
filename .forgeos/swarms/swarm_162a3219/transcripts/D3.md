## Predicate (Phase-1a-revised)

The detector flags a completion call where ALL hold:

1. The receiver name ends in `completion` (case-insensitive on the `C/c`),
   with optional `?.` chaining (e.g. `completion`, `self.completion`,
   `self?.completion`).
2. The first positional argument is exactly `nil`.
3. At least one of args 2..N is a TOP-LEVEL String-typed expression:
   - bare string literal `"..."`,
   - bare interpolated string `"...\(...)"`,
   - bare `NSLocalizedString(...)`,
   - `Strings.<...>` constant chain ending at an identifier (Palace ns), OR
   - a bare identifier `title` / `message` / `errorTitle` / `errorMessage`
     bound to a string via `let <name> = "..."` (or `Strings.<…>` /
     `NSLocalizedString(...)`) earlier in the same function body.

False-positive guards (explicit, structural):

- `completion?(nil, nil, nil)` — all-nil success path
  (`Palace/SignInLogic/TPPSignInBusinessLogic+OAuth.swift:244`, verified).
- `completion?(nil, response, error)` — failure-passthrough with error in
  position 3 (`Palace/Network/TPPNetworkExecutor.swift:464,484`).
- `completion(nil, nil, DPLAError.requestError("..."))` — string literal
  nested INSIDE an Error constructor is NOT a top-level String arg
  (DPLA `(Data?, Date?, Error?)` callback signature).
- `delegate?(nil, "title", "message")` — receiver does NOT end in
  `completion`.

Annotation escape hatch: `// no-nil-error-suppression: <reason>` on the call
line or any of the 3 preceding lines.

## False-positive discovery + fix during implementation

First-pass predicate `re.search(r'"[^"]*"', stripped)` was too permissive —
it matched ANY string literal nested inside an arg, including inside an
`NSError(...)` or `XError.case("msg")` constructor. This false-positive'd
5 sites:

```
Palace/Audiobooks/DPLA/DPLAAudiobooks.swift:67    # (Data?, Date?, Error?) — error in arg 3
Palace/Audiobooks/DPLA/DPLAAudiobooks.swift:76    # same shape
Palace/Audiobooks/LCP/LCPAudiobooks.swift:131     # (File?, Error?) — error in arg 2 (NSError ctor)
Palace/Reader2/.../LicensesService.swift:37       # (URL?, Error?) — error in arg 2 (XError case)
Palace/Reader2/.../LicensesService.swift:42       # same shape
```

These are NOT the PP-4419 bug class — they correctly carry the error in a
non-arg-1 position. The detector was tightened to require args 2-N be a
TOP-LEVEL String-typed expression (bare literal / interpolated / bare
`NSLocalizedString(...)` / `Strings.<...>` / let-bound title-message
identifier) — NOT a string literal nested inside an Error constructor.

After the fix: 0 survivors, all 8 tests pass, OAuth+244 success path
unaffected.
