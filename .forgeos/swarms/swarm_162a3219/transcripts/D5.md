## Decisions

### Detector design

- **Mirror the sibling detector shape exactly.** Same argparse surface, same exit-code model (0 / 1 / 2), same severity-floor ladder, same `_checklib` shared primitives. The implementer convention is established by 7+ existing `check-*.py` detectors. The only departure: severity-floor default is `medium` (matches the contract's D5-1 severity).

- **Type-body splitter, not function-body splitter.** Per-class predicate: a class with `removeObserver(self)` in deinit covers every observer added against that instance, regardless of where in the body the addObserver call lives. Slicing by function would force per-function lookups for the cleanup evidence, missing the textbook fix shape. Brace-depth heuristic mirrors the lenient style in the sibling detectors.

- **Multi-line addObserver handling.** PP-4329's canonical fix in `TPPAppDelegate.swift:473` is multi-line (`NotificationCenter.default.addObserver(` on one line, `forName:` on the next). A same-line-only regex would miss every modern Swift call site and produce zero findings on the bug it's named for. The detector recognizes both shapes via a tolerant opener + 3-line look-ahead for `forName:`.

- **Two operating modes:** `--scan <root>` walks `<root>/Palace/**/*.swift` for the wipe and architect dry-runs; `--diff <file>` reads a unified diff (defaults to stdin / staged) and reports findings on touched lines only — the same convention every other M1 detector uses to avoid blocking PRs on pre-existing untouched leaks.

### Survivor handling

`develop` HEAD (post-PP-4329 fix at 0bbbf2b4a) has 2 survivors, both in `Palace/Notifications/NotificationService.shared`:

- `NotificationService.swift:139` — `.TPPCurrentAccountDidChange` observer
- `NotificationService.swift:143` — `.TPPIsSigningIn` observer

`NotificationService.shared` is a `static let shared` — Swift guarantees one-shot init. Observer-lifetime ≈ process-lifetime. The PP-4329 "stack on re-init" failure mode is structurally impossible here. The cheap, correct fix is the annotation escape, not a refactor to add `private var observerA: NSObjectProtocol?` + `deinit` (deinit on a `static let` never fires). Annotated both with rationale.

### Out of scope (architect-confirmed)

- **Selector-form `addObserver(_:selector:name:object:)`** — has no return token, different bug class.
- **KVO observers** — different API surface.
- **Combine subscriptions** — different API surface; covered by other detectors (e.g. retain-cycle review).
- **Real refactor of NotificationService** — would force unwiring `static let shared` (touches every observer + every `NotificationService.shared` consumer), out of scope per the "cheap fixes only" survivor-wipe rule.
