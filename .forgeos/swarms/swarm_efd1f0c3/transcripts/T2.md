## Implementation notes

### Continuation box design

Both `SingleResumeContinuationBox<T>` and `SingleResumeThrowingContinuationBox`
follow the same pattern:

```swift
final class SingleResumeContinuationBox<T> {
  private var continuation: CheckedContinuation<T, Never>?
  private let lock = NSLock()

  func attach(_ continuation: CheckedContinuation<T, Never>) { ... }

  func resume(returning value: T) {
    lock.lock()
    let cont = continuation
    continuation = nil
    lock.unlock()
    cont?.resume(returning: value)  // outside the lock to avoid reentrancy
  }
}
```

The lock is held ONLY around the slot read+nil; the actual resume happens
outside the lock to avoid reentrancy if the continuation's downstream awaiter
turns around and calls into FindawayPlayer (it doesn't today, but the
discipline is cheap).

### Findaway internal seams renamed

Old (T1 bridge naming):
- `skipPlayheadCallback(_:completion:)`
- `playCallback(at:completion:)`
- `moveCallback(to:completion:)`

New (T2 final naming):
- `performSkipPlayhead(_:completion:)` — internal-only
- `performPlayAt(_:completion:)` — internal-only
- `performMove(to:completion:)` — internal-only

Plus existing `move(to: TrackPosition, completion:)` was renamed to
`moveToTrackPosition(_:completion:)` to disambiguate from the public
async `move(to value: Double)`.

### Why `Task { ... }` blocks in AudiobookManager/AudiobookPlaybackModel stay

The contract said "no callback shims remain." After audit, the `Task { ... }`
blocks at the BRIDGE-marked sites are NOT shims — they're the canonical
sync→async hop primitive when calling an async method from a Combine
`.sink` closure or a property `didSet`. Both contexts are sync; there's no
async parent to inherit from. Removing the `Task` would be a compile error.

The BRIDGE markers were T1's "audit this — do you need to migrate the
caller's surface upward?" prompts. Audit result: the callers (remote
commands, didSet observers, Combine sinks) can't be made async without a
broader refactor that's out of swarm scope (e.g., making AudiobookPlaybackModel
an actor, or routing every UI hop through Tasks). Decision: keep the
Task hops, remove the markers, document the rationale here.
