## What shipped this attempt

### Summary

Migrated the toolkit's `Player` protocol from completion-handler shape to
`async/await`. Three methods change atomically:

```swift
func skipPlayhead(_ timeInterval: TimeInterval) async -> TrackPosition?
func play(at position: TrackPosition) async throws
func move(to value: Double) async -> TrackPosition?
```

`OpenAccessPlayer` and its subclass `LCPStreamingPlayer` migrate in
lock-step (Swift `override` signature matching enforces this). The new
async methods bridge to the existing callback impls via
`withCheckedThrowingContinuation` / `withCheckedContinuation` so the
well-exercised LCP fast-path (`isSeekingWithinSameTrack` flag, queue
rebuilds, safeTimestamp clamp) is preserved verbatim.

`seekTo` stays callback-shaped (decision pre-locked by previous attempt;
see "Pre-flight findings" section preserved below).

### seekTo decision — KEEP CALLBACK (option 2 per contract)

Rationale:
- seekTo is `public` but NOT part of the Player protocol — it's a class
  method on OpenAccessPlayer that LCP overrides. Migrating it doesn't
  contribute to the contract's three required protocol-method migrations.
- LCP override carries critical state-flag logic (`isSeekingWithinSameTrack` +
  `asyncAfter(0.5)` clear) that translates poorly to async/await without
  introducing a continuation race against the deferred flag clear.
- AudiobookManager.swift:219 (T2 territory) calls seekTo directly — keeping
  it callback-shaped means T2 picks up ZERO additional churn.
- Contract explicitly permits this.

LOC impact:
- Migrate seekTo to async: ~40 LOC churn (LCP rewrite + async wrapper + T2
  call-site edit).
- Keep seekTo callback (CHOSEN): 0 LOC churn beyond the protocol three.

T2 handoff: seekTo remains callback-shaped. T2's AudiobookManager.swift:219
call site does not need to change.
