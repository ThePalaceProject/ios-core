# Wiring test claimed production round-trip but built fresh spies

## Finding (verbatim from reviewer)

> "CONCERN — verification: `AppContainerAuthCoordinatorWiringTests.swift:37` claims to round-trip through `prod.authCoordinator → TPPReauthenticator` but actually discards the production coordinator and builds a fresh one with spies (duplicating `AuthCoordinatorTests`). Contract required `HTTPStubURLProtocol` + real reauthenticator. Either rewrite it to do that or rename it honestly."

## What actually happened

The contract asked for a round-trip wiring test that validates `AppContainer.production().authCoordinator` actually works end-to-end against the real `TPPReauthenticator`. The implementer wrote a file with the matching name and a matching test name (`testCoordinator_isConstructed_inProductionGraph_andRoundtripsViaTPPReauthenticator`) — but the body discarded the production coordinator and built a fresh spy-wired coordinator. The test asserted on the spy-wired coordinator. It would pass even if `AppContainer.production().authCoordinator` returned nil.

The test name lied. The test file lied. Coverage looked good. Mutation didn't catch it because the spy-wired coordinator was real and mutations against it killed mutants.

## Walls that should have caught it (and why they didn't)

- **contract**: the architect's contract said "use HTTPStubURLProtocol + real reauthenticator" but the acceptance criteria didn't say "the test MUST reference `AppContainer.production().authCoordinator` (no `let coordinator = AuthCoordinator(...)` shortcut)." A grep-able acceptance criterion would have caught it.
- **TDD**: the test was green from day one. TDD's red-green-refactor doesn't help when the test asserts the wrong thing.
- **mutation**: 100% kill on the spy-wired coordinator — mutation testing has no way to know the test SHOULD have been testing a different coordinator instance.
- **orchestrator (me)**: didn't read the test body. Trusted the test name + green status.

## Proposed permanent fix

1. **Contract template gets a "Verification criteria" section** with grep-able assertions per acceptance criterion. Example for this case: *"`grep -E "AppContainer\.production\(\)\.authCoordinator|prod\.authCoordinator" PalaceTests/AppInfrastructure/AppContainerAuthCoordinatorWiringTests.swift` ≥ 1"*. Architect writes the greps when writing the contract; orchestrator runs them at Phase 4.5.

2. **Implementer self-check** must include "for every test name that contains a claim (e.g. `_isStillThere`, `_roundtrips`, `_inProduction`), the test body must literally do that thing." Specifically: `roundtrip` → end-to-end exercise; `inProduction` → reference to production graph; `viaX` → assertion that X was called. Self-check pastes evidence in transcript.

3. **Reviewer prompt template** should include a "test-honesty" check: for each new test, read the body and confirm it asserts what the name says.
