# Circuit-breaker test ran ONE attempt; second half was comments

## Finding (verbatim from reviewer)

> "FAIL — `PalaceTests/MyBooks/BorrowOperationAuthCoordinatorTests.swift:260` `testCoordinator_perBookCircuitBreaker_isStillHonored_acrossTwoSeparateAttempts` runs ONE attempt and asserts modal=1; the second-attempt half is just comments. Fluff test by CLAUDE.md."

## What actually happened

The test name claims to verify the per-book circuit breaker prevents a second reauth attempt for the same book. The test body:
1. Drives ONE borrow attempt
2. Asserts the coordinator was called once
3. Has a commented-out section that *describes* what the second attempt should look like
4. Does NOT actually drive a second attempt
5. Does NOT assert that the coordinator was NOT called a second time

The breaker's whole purpose is preventing the second call. The test for the breaker doesn't test the second call. This is the canonical CLAUDE.md fluff pattern: "test names X but doesn't exercise X."

It compiled. It passed. It gave the appearance of breaker coverage. A future refactor that broke the breaker would NOT trip this test. The test was actively misleading about the safety net.

## Walls that should have caught it (and why they didn't)

- **implementer**: implementer wrote the test, marked it READY. Self-check on test-name-vs-body would have caught it. (Same fix as arch2.)
- **mutation**: mutation on the breaker's production code (`hasBorrowReauthBeenAttempted`) would have killed mutants only if the second-attempt path was tested. Since it wasn't, mutations against `if hasBeen → if !hasBeen` would have survived. Mutation testing was deferred to integrator, so this wasn't run.
- **TDD**: this is exactly the case TDD's red→green is supposed to catch. The test was never red against the breaker behavior because the second-attempt step was never written. The "red" step was skipped.
- **contract**: contract specified "round-trip wiring tests per CLAUDE.md `feedback_round_trip_wiring_tests`" which requires "write → reset → re-enter via production seam." This test does the "write" half and stops. Contract acceptance should have asserted "test must include all three phases."

## Proposed permanent fix

1. **Implementer self-check (overlap with arch2/3):** for every test with `across`, `twice`, `reset`, `retry`, `again` in the name, the body must contain ≥2 calls to the production driver. Grep: `grep -c "<driver>(" <body-section>` for the test body region.

2. **Mutation-as-implementer-completion-gate:** implementer cannot report READY until mutation rates meet contract on every modified file. A test class with green tests + low mutation kill on the underlying production code = block. For this case: mutation on `Palace/MyBooks/BorrowOperation.swift` around the breaker code would have shown survived mutants.

3. **Contract template "Verification criteria":** for round-trip tests specifically, require an assertion of FORM, not just behavior. Example: *"`grep -c 'borrowAsync\|circuit.*reset' <test-body>` must be ≥ 2 (write → re-enter cycle exercised)."*

4. **Reviewer prompt:** for any test with multi-step name, read the body and confirm each step has an assertion.
