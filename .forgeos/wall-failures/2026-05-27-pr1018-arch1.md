# Submodule gitlinks accidentally staged as absolute-path symlinks

## Finding (verbatim from reviewer)

> "FAIL — discipline: Staged diff converts 7 git submodules (`adept-ios`, `adobe-content-filter`, `ios-audiobook-overdrive`, `ios-tenprintcover`, `mobile-bookmark-spec`, `readium-sdk`, `readium-shared-js`) from gitlinks to absolute-path symlinks pointing at `/Users/mauricework/...`. This is the worktree-setup hack leaking into a commit; would break the build on every other machine. `git restore --staged` these 7 paths before the integration commit."

## What actually happened

The swarm worktree setup symlinks 7 of the 8 submodules to the main checkout's clones (to save disk + setup time). Git sees those symlinks as a `T` (type change) in the worktree. The implementer ran `git add` (or `git commit -a`) and pulled them into the staging area along with their real work. The orchestrator (me) didn't filter them out at integration time; the reviewer caught it.

The damage if it had landed: every other contributor's `git pull` would fail with "would replace tracked submodule with symlink" errors. CI would fail because the symlink targets don't exist on CI workers.

## Walls that should have caught it (and why they didn't)

- **implementer**: the implementer staged the typechange. They didn't run `git diff --cached --name-only` to audit what they were about to ship. Self-check is missing this assertion.
- **orchestrator**: I did stage-inspection but didn't notice the `T` entries. The git status output's first-column-blank for the typechanges made them visually indistinguishable from intentional `M` entries until you look at the type code.
- **hook**: no pre-commit hook blocks `T` typechanges on submodule paths. This would be a deterministic fix.

## Proposed permanent fix

Three layers, defense-in-depth:

1. **Add to swarm SKILL.md Phase 4 (integrator skeptic pass):** before staging anything, run `git status --short | grep "^T \|^ T \|^TT" && exit_with_block("submodule typechanges detected — do NOT stage")`. Make it a literal command in the skill, not a discipline.

2. **Add to swarm SKILL.md Phase 0 worktree setup:** after symlinking submodules, run `git update-index --skip-worktree` on each symlinked submodule path so git stops reporting the typechange entirely. This makes the failure mode structurally impossible.

3. **Add pre-commit hook check:** `pre-commit-typechange-check.sh` that blocks any commit including a `T` status on a `.gitmodules`-listed path. Hard gate; can't be bypassed without `--no-verify`.

The fix should make the finding **structurally impossible to land**, not "more likely to be noticed."
