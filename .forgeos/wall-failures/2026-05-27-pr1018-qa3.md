# BookReturnServiceAuthCoordinatorTests never instantiated BookReturnService

## Finding (verbatim from reviewer)

> "CONCERN — `PalaceTests/MyBooks/BookReturnServiceAuthCoordinatorTests.swift` (3 tests) never instantiates `BookReturnService`; all 3 hit the coordinator directly. Service's coordinator-routing branch unverified at the service seam."

## What actually happened

Same pattern as qa2, different SUT. The test file was named `BookReturnServiceAuthCoordinatorTests` — three tests claimed to verify that the service routes auth errors through the coordinator. The bodies constructed coordinators directly and asserted on coordinator behavior. `BookReturnService` was never instantiated.

The service's `if isAuthError` branch was migrated to call the coordinator (this part was real, unlike arch3). But the test never exercised the migrated branch. The test would pass even if the service's migration was reverted, because the test never touched the service.

Coverage tools showed the file at high coverage because the new file existed and its assertions were hit. The fact that the assertions weren't about the SUT didn't show up in any coverage metric.

## Walls that should have caught it (and why they didn't)

- **contract**: same gap as qa2. Acceptance criteria specified spy + assertions but not SUT instantiation.
- **implementer**: same as qa2.
- **orchestrator (me)**: same as qa2. Both files reviewable with the same grep.
- **TDD + mutation + coverage**: same blindness as qa2.

## Proposed permanent fix

Identical to qa2's three-layer fix. The Verification criteria + Implementer self-check + Orchestrator skeptic pass closes both findings simultaneously — that's the value of the cluster-level fix.

Documenting separately because:
1. The catalog should record each finding individually so future analysts can compute cluster sizes accurately.
2. If the cluster fix proves insufficient (a third instance of this class slips through despite all three layers), this entry is the second data point that says "the fix isn't working — escalate."
