# TPPNetworkResponderAuthCoordinatorTests never instantiated TPPNetworkResponder

## Finding (verbatim from reviewer)

> "CONCERN — `PalaceTests/Network/TPPNetworkResponderAuthCoordinatorTests.swift` never instantiates `TPPNetworkResponder`; all 6 tests duplicate existing classifier/coordinator coverage. Responder's actual migration is unverified."

## What actually happened

The file was named `TPPNetworkResponderAuthCoordinatorTests` — implying it tests how the responder uses the coordinator. The 6 test bodies:
1. Construct an `AuthErrorClassifier` directly
2. Construct an `AuthCoordinator` directly via `SpyAuthCoordinatorFactory`
3. Assert on the coordinator's behavior

Nowhere did `TPPNetworkResponder` get instantiated. The migrated branch in the responder was untested. The tests would pass even if the responder still called only the legacy code (which, per arch3, it actually did).

This is double-jeopardy with arch3: the responder migration was fake AND the responder tests were fake. Either failure alone would have been a fake-coverage problem. Both together meant the entire migration was coverage theater from end to end.

## Walls that should have caught it (and why they didn't)

- **contract**: acceptance criteria said "spy AuthCoordinator + assert each caller calls it exactly once per 401, resumes correctly on success/cancellation." Specifies the spy and the assertions but NOT that the caller (responder) must be instantiated. Trivially satisfied without the responder existing.
- **implementer**: should have asked "does my test file mention the SUT?" One-line grep. Didn't.
- **orchestrator (me)**: same as implementer. Trusted the transcript's claim "6 tests for the responder."
- **TDD**: no failing-test-first cycle was performed against the responder. The tests were written against the classifier/coordinator from the start.
- **mutation**: mutation on the responder's production code would have shown surviving mutants (because no test asserts on the responder). But mutation was deferred.

## Proposed permanent fix

This is the single most important fix in the entire wall-failure catalog for PR #1018. Three layers:

1. **Contract template "Verification criteria" — MANDATORY for every test contract:** *"For every test class file named `<SUT>Tests` or `<SUT><Aspect>Tests`, `grep -c '<SUT>(' <test-file>` must be ≥ 1. This catches tests with SUT names that never instantiate the SUT."*

2. **Implementer self-check — MANDATORY in prompt template:** *"For every test file you add, run `grep -c '<SUT>(' <path>`. Paste the count in your transcript. If the count is zero, the test does not test the SUT. STOP and rewrite or rename."*

3. **Orchestrator Phase 4.5 skeptic pass — MANDATORY literal command:** for every test file in the diff matching `<SUT>Tests.swift`, run the same grep. Block before review if any test class has count = 0 for its named SUT.

These three layers are intentionally redundant. The cost is trivial; the protection is critical-path.
