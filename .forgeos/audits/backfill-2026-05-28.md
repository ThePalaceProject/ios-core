## Methodology

For each PR:

1. **Resolve final commit.** Merged PRs → `gh pr view <num> --json mergeCommit -q .mergeCommit.oid`. Unmerged PRs → diff against the PR's base branch (not just the last commit, because the unmerged PRs are scaffolds with multiple landed commits the M1 floor would have evaluated at PR-create time).
2. **Build the diff.** Merged → `git diff <sha>^...<sha>`. Unmerged → `git diff origin/<base>...origin/<head>` to capture the full branch delta.
3. **Fetch the PR body.** `gh pr view <num> --json body -q .body`.
4. **Run all 4 scripts.** Each script takes `--diff <path>`; the reconciler also takes `--pr-body <path>`. Other scripts ignore the PR body (it's optional input the contract didn't require for them — verified in their `--help`).
5. **Categorize findings.** `BR-N: high|medium|low:` for blast-radius; `UNSUPPORTED:` for reconciliation; `ADJ-STALE:` for adjacency; `INTENT-MISSING|INTENT-INVALID:` for intent.
6. **Flag NEW high-severity findings.** Cross-reference against `.forgeos/wall-failures/INDEX.md`. A finding is "NEW" if no existing entry covers the same file + same rule + same root cause.

Invocation pattern used (one of 4×6 = 24 runs):

```bash
python3 scripts/check-blast-radius.py --diff /tmp/m1-backfill/pr-1018.diff
# exit 1 → 49 findings, all BR-1 high, listed by file:line
```

## Caveats + false-positive notes

1. **SPM-package source files require `public` for cross-target visibility.** The blast-radius scanner does not currently distinguish `Palace/Packages/<pkg>/Sources/<pkg>/*.swift` from main-target Palace source files. Of PR#1018's 49 findings, roughly 30 are inside the PalaceAuth SPM package and are structural false positives — they need `public` to be linkable from `Palace`. The 19 main-target findings (AuthDecisionEvent, AuthDecisionRecorder, TPPReauthenticator extension) remain real concerns. **Follow-up M2 task:** teach `check-blast-radius.py` to recognize `Palace/Packages/<pkg>/Sources/<pkg>/` as SPM-source and suppress BR-1 there (or emit BR-1 at `medium` severity since SPM `public` is still surface-exposed even if structurally required).

2. **Reconciler depends on commit-subject ↔ intent name match.** All 4 INTENT-MISSING findings in the backfill stem from "no commit subject to match an intent file against." The reconciler emits this when no commit subject is provided AND the diff exceeds the threshold. In CI/verify-pr.sh, the commit subject is derived from `git log -1 --pretty=%s` and works fine. In a backfill audit where we feed a flat unified diff without a paired commit message, the script correctly degrades to INTENT-MISSING — informative, not a script bug.

3. **PR#1024 cannot be audited.** Documented in §SHA-resolution. PR#1021 substituted for coverage parity.

4. **Stacked-PR baseline.** For unmerged stacked PRs (#1020, #1022, #1023), we diffed each PR's base branch against its head branch (per-PR delta) rather than diff-from-develop. This matches what the M1 floor would have seen at PR-creation time for each scoped PR and avoids double-counting findings across the stack.

5. **Confidence:** medium-high on the claim-drift finding (#1022/#1023 — the reconciler logic is unambiguous), medium on the blast-radius cluster (subject to the SPM caveat above), high on the intent-missing baseline (mechanical — every pre-M1 PR over the threshold flags).
