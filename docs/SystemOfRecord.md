## Architectural decisions

### `Accounts`

Library registry crawling uses a separate LibraryRegistryCrawler service rather than extending AccountsManager. The crawler handles paginated OPDS 2.0 feed fetching, incremental vs full crawl strategy (based on order=modified facet detection), and merging via LibraryCatalogMerger. The disk cache always stores the full merged catalog in OPDS2CatalogsFeed format, preserving backward compatibility. CrawlState (lastSuccessfulCrawlDate, orderModifiedFacetURL) is stored separately from CatalogCacheMetadata. Logo cache entries are invalidated when thumbnailURL changes during merge. Catalog feeds for active accounts are preloaded after crawl completion.

## Anti-patterns and hazards

### `Audiobooks`

PalaceAudiobookToolkit (git submodule) is the highest-risk dependency in the project. Updated 25+ times across releases with frequent regressions requiring reverts. Specific failures: (1) 2.0.2→2.0.4: 3-phase adaptive memory management added, partially abandoned, (2) 2.0.5→2.1.0: audiobook location race conditions and concurrency crashes, (3) 2.2.3→2.2.4: manifest fetch used wrong task type and skipped bearer token dance — a fundamental API contract violation that shipped to production. Each audiobook fix risks breaking another playback path (Findaway, OverDrive, LCP, open-access) because all share the same player infrastructure.

### `MyBooks`

TPPUserAccount.sharedAccount() (legacy singleton) is still a fallback path in AccountsManager.currentUserAccount when currentAccountId is briefly nil. The singleton's mutable libraryUUID is re-pointed on every sharedAccount(libraryUUID:) call, and its keychain-backed hasCredentials() returns false transiently after a libraryUUID flip (before updateKeychainKeys re-fetches). Any download or auth check that hits `currentUserAccount` during that narrow window can observe hasCredentials==false on a library that IS actually signed in → spurious login modal. Suspected cause of the PP-TBD "login prompt during download" regression. Follow-ups: (1) capture accountId at download start in MyBooksDownloadCenter and pass it explicitly through bearerAuthorized / request(for:); (2) consider making currentUserAccount stable across transient currentAccountId==nil windows by remembering the last known id, or (3) eliminate the sharedAccount() fallback entirely by making currentUserAccount return a last-known-good instance.

## Fix recipes

### `tooling/regression`

When a shell wrapper delegates to a Python script that supports both --validate (validate-and-exit) and --output (generate-and-write), DO NOT pass --validate alongside --output in the same call — argparse's --validate triggers sys.exit(0) before generation runs, so the file is never written. Split into two calls: first python --validate (fast, exits non-zero on bad input), then python --output (generation). Verify the output file exists after the generation call before printing 'Report generated at:' — the script's own optimism shouldn't be load-bearing. This was BLOCKER #12 in the regression skill dogfood pass on PP-4164: regression-report.sh's cmd_report passed --validate unconditionally, the python generator exited cleanly, and the shell happily printed success while the HTML never landed on disk.

_Confidence: 0.95_

### `tooling/regression`

When orchestrating mutation testing across many source files, derive the per-file XCTest class name (NOT a directory). xcodebuild's `-only-testing:PalaceTests/` (no class suffix) runs the entire test suite, which on Palace exceeds palace_mutate.py's 600s baseline timeout. The fix: implement derive_test_class_for(source_file) that (1) tries `<basename>Tests.swift` under PalaceTests/, (2) falls back to grepping any test file mentioning the source class, then (3) extracts the first XCTestCase subclass name from that file via awk. Note: filename-to-classname is not 1:1 — `TPPBookRegistryTests.swift` actually contains 7 distinct classes (TPPBookRegistryRecordPersistenceTests, TPPBookRegistryDataTests, etc.), none named `TPPBookRegistryTests`. The grep-fallback is mandatory. Add `--mutation-test-class CLASS` for explicit override per file. This was BLOCKER #13 in the regression skill dogfood pass on PP-4164: 50 minutes of compute produced zero kill data because every file timed out at the baseline run.

_Confidence: 0.95_
