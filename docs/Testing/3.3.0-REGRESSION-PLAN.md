Every module in the app was touched. This is not a point release with a few fixes, and it
should not be regression-tested like one.

### The four whole-app changes

These carry more risk than any individual feature, because their failure mode is a crash, a
hang, or a silently wrong persisted value rather than a wrong screen — so no feature row
catches them. They are matrix rows **PR1–PR4**:

1. **Swift 6 language-mode flip** (31 `fix(swift6)` commits + `SWIFT_VERSION` 5.0 → 6.0).
   Strict concurrency converts previously-silent main-actor violations into hard traps. The
   regression signal is a *new crash class*, not a changed screen.
2. **Readium 3.9.0 → 3.11.0** (PP-4848). A reader-engine swap can change locator encoding
   without changing a single Palace source line — invisible to a diff-scoped review and to
   every unit test that round-trips through our own types.
3. **iOS 17 deployment floor** (16.0 → 17.0, both targets + 7 SPM packages). Newer-OS-only
   API adopted since must degrade rather than crash on the floor.
4. **Package extraction, decomp Waves 1–3** (`PalacePreferences`, `PalaceFeatureFlags`,
   `PalaceBookModel`, `PalaceBookRegistry`, Accounts/Downloads seams). Each wave claimed to
   be behavior-preserving and each was gated on a green suite — but moving a singleton read
   behind a protocol changes *when* state resolves, which a suite can miss. Credential
   isolation (**A6**) is the highest-consequence cell.

## 3. Coverage audit — what was missing, and what was done about it

The audit asked one question per surface: does a patron-reachable change since 3.2.0 have a
matrix row, a journey, and a unit test?

**The unit layer kept pace.** 712 test files changed in the same window; every feature probed
(rating, sideload, skip interval, sleep timer, skeletons, mini-player, rotor a11y, footnotes,
keychain corruption, catalog branding, offline catalog state, feature-flag gates) resolved to
real test files. The one surface with no direct unit coverage is the `HelpButton` entry point.

**The release-regression layer did not.** The matrix was last re-derived on 2026-07-08 and had
zero rows for surfaces a patron can now reach. Two concrete defects were found and fixed:

### Finding 1 — 26 patron-reachable surfaces had no matrix row

Added (matrix went 66 → 92 rows): `PR1–PR4`, `E9`/`E10`,
`E3-Skip/Sleep/Speed/Mini/Icons/Stream`, `C5–C7`, a new **Support & Feedback** section
(`S1–S4`, `R1–R2`), `U3-Footnote/PrintPage/WhereAmI/BlockNav/SearchFocus`, `U5`/`U6`, and
`X7–X9`. See the matrix change log for the full derivation.

### Finding 2 — 8 of 33 recorded journeys never ran

`.simdrive/regression-areas.json` is the shard key: a campaign worker is one
`(area-group × device-cell)`, and a journey no area group claims is never fanned to any cell.
Eight journeys existed on disk, passed their own lint, and **were executed by nothing**:

```
PP-4529-print-page-navigation-voiceover   app-rating-sentiment-gate
audiobook-sleep-timer-45                  holds-reservations-empty
reader3-pdf-open-and-page                 triage-bot-category-chip-rapid-tap
triage-bot-redaction-adversarial-input    ws4-ipad-on-mac-exit-adobe-drm
```

That list includes **`triage-bot-redaction-adversarial-input`** — the guard against sending a
patron's typed password or card number to a support queue. It was recorded, committed, and
dormant.

A journey no cell claims is indistinguishable from a journey that passes. Fixed by adding a
`support` area group and adopting the orphans into the groups that own their matrix rows.
`ws4-ipad-on-mac-exit-adobe-drm` is the one legitimate exception — it is an interactive
protocol driven by `scripts/regression-ipad-on-mac.sh`, not a replayable recording — and the
manifest now records *why* it is unassigned so the next audit does not "fix" it.

### Finding 3 — a stale device-cell label

`C-ios18` was documented as the "back-compat floor (iOS-16 substitute)". The floor is now
iOS 17.0. The cell sits one minor version *above* the floor rather than substituting for it.
Corrected in the manifest; matrix row **PR3** owns the true-floor check.

## 4. Known-open defects — confirm, do not rediscover

These are already diagnosed. The regression's job is to record whether they still reproduce,
not to spend a session re-deriving them. **Filing a duplicate is a worse outcome than not
testing the row.**

| Row | Defect | State |
|---|---|---|
| **X8** | Hidden Libraries toggle deadlocks the app — process alive, 0.0% CPU, state `Ss`, all touch input refused ~5 min, zero log lines at any level. Reproduced by two independent chaos agents on different sims (2026-08-10 sweep, off `b2f47552b`). The `.TPPUseBetaDidChange` notification path and the publisher path are **cleared** — do not re-investigate them. | Open, expected to fail |
| **E10** | Long screen-locked playback loses position. The autosave chain sits entirely on the main runloop, which iOS coalesces during background playback. Four position fixes shipped across 3.2.x/3.3.0 and complaint volume is flat because those fixed *which* position is written; this is about *when*. 25 of 83 App Store reviews Jan–Aug 2026 are "the app forgot where I was." | Open, unmeasured on device |
| — | `Account.awaitReady()` census: three call sites had no enclosing timeout while each carried a comment asserting one did. One arm bounded (#1372); the rest were dropped by owner decision for lack of a reproducer. Symptoms if they surface: LCP first-open hang, bookmark loss, CarPlay dead-tap. | Partially bounded by decision |

## 5. Execution plan

Five legs. Legs A and B are done; the rest need a driven device or simulator.

| Leg | Scope | Tool | State |
|---|---|---|---|
| **A — Unit + integration** | Full `Palace` scheme, both test targets, CI parity (`-test-iterations 3 -retry-tests-on-failure`) | `scripts/xcode-test-optimized.sh` | ✅ **Passed** — see §6 |
| **B — Tooling gates** | Manifest integrity, detector pytests, hook wiring | `pytest scripts/tests/` | ✅ 52 passed |
| **C — Journey replay** | Every journey in every area group, per device cell | `scripts/simdrive-regress.sh`, `scripts/regression-area-worker.sh` | Pending |
| **D — Chaos** | Adversarial exploration from fixture seeds | `scripts/run-chaos-pass.sh`, `scripts/regression-chaos-fan.sh` | Pending |
| **E — Manual matrix** | P0 → P1 → P2 side by side against 3.2.0; everything marked Manual, especially `UP1` (in-place upgrade) and the VoiceOver rows | Human + `simdrive` | Pending |

**Leg E is not optional and not substitutable.** The rows that carry the most consequence —
in-place upgrade over real 3.2.0 state, VoiceOver rotor navigation, Adobe/LCP fulfillment on a
real device, CarPlay — are the ones no automation reaches. Readium renders into a WKWebView
that XCTest cannot see; rotor items do not appear in screenshots; and `UP1` requires prior-version
state that a clean install cannot manufacture.

## 6. Leg A result (recorded)

Run against `ff3b1227c` on iPhone 17 Pro / iOS 26.1, read from the result bundle rather than
summed from per-suite log lines:

```
result            Passed
totalTestCount    8360
passedTests       8221
failedTests       0
skippedTests      137
expectedFailures  2
```

`** TEST SUCCEEDED **`. Zero `exceeded execution time allowance` and zero
`Restarting after … test timeout` lines — a timeout is a failure even at a 0-failure tally, so
this was checked explicitly rather than inferred from the verdict.

One caveat worth stating: a grep for `error:` in the build log returns 11 hits. All 11 are
`archivedData(withRootObject:)` deprecation **warnings** whose suggested replacement selector
is literally named `...requiringSecureCoding:error:`. They are not failures. They do point at
real deprecated `NSKeyedArchiver` use in `TPPNetworkQueue.swift` — the offline queue that
**E9-Offline-Sync** exercises — which is worth a follow-up ticket but is not a release gate.

## 7. What this plan does not cover

Stated so the gaps are chosen rather than discovered:

- **Real-device DRM.** Adobe RMSDK and LCP fulfillment behave differently on device than on
  simulator. Leg C/D evidence is simulator evidence.
- **LCP audiobook streaming** (PP-4957) ships with its flag **false**. Row `E3-Stream` verifies
  the flag-off path. The streaming path was accepted on simulator evidence and still owes a
  device pass before it is ever enabled.
- **CarPlay** (`X2`) runs as a headless XCTest cell, not a driven UI.
- **Push notifications** (`N1`–`N4`) need a Firebase service account and a real APNs round trip.
- **Mutation testing** is not run per-PR in CI; the release regression is the only place a
  mutation signal is produced for the candidate. It is not yet run here.
